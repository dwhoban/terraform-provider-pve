# Changelog

## 0.2.0 (unreleased)

Phases 2–13 — the full declarative surface, **generated from the API schema** ([ROADMAP.md](ROADMAP.md)):

- Generated provider architecture: `go run ./gen` parses the checked-in `apidoc.js` (449 API path families), combines it with the phase mappings (`gen/mapping/`), audits complete coverage (every family used exactly once, out-of-scope families never referenced), and emits `internal/provider/registry.json`, the ROADMAP Appendix A table, and per-type examples. Four generic runtime engines (resource / data source / action / function) interpret the registry — no per-type hand-written provider code.
- 222 types across all phases: inventory data sources (`pve_cluster`, `pve_node*`, `pve_storage_scan_*`, …), guests (`pve_vm`, `pve_container` with clone-at-create, snapshots, and lifecycle/bulk actions), storage & pools (`pve_storage`, `pve_pool`, `pve_file`, …), node system management (`pve_node_network` with PVE staged-apply semantics, singletons for DNS/time/hosts/config, disk management, services, APT, power actions), RBAC (`pve_user`, `pve_api_token` capturing the one-time token value, `pve_acl`, `pve_realm`, …), cluster lifecycle & mappings, data protection (`pve_backup_job`, `pve_replication_job`, HA), scoped firewall (cluster/node/vm/container), SDN, Ceph, and integrations (notification endpoints/matchers, metric servers, ACME, node certificates).
- Provider functions `nextid()` and `schedule_analyze()`; framework actions for all one-shot operations (Terraform ≥ 1.14).
- `terraform import` support for every resource; task-waiting (UPID polling) is built into the engines.
- Client: generic request layer + not-found detection covering PVE's 404/500 "no such …" spellings.
- Optional SSH access (the pattern popularized by bpg/proxmox): provider `ssh { … }` block (agent / private key / password, `node` address overrides, `known_hosts` host-key verification, `PVE_SSH_*` environment variables), used only where the API cannot do the job. New action `pve_ceph_install` (`pveceph install` over SSH, idempotent via an API probe, strict argument validation, `sudo -n` for non-root users with a documented regex sudoers rule) and opt-in `ssh.root_ticket` (mints a `root@pam` ticket on the node for `/nodes/{node}/…` calls so an API token can perform root-only operations). Connections are lazy; commands are argv vectors with every argument single-quoted. Ceph endpoints now explain "binary not installed" and point at `pve_ceph_install`. New guide: "When is SSH required?".
- Live acceptance (Phase 11 SDN): zone/vnet/subnet CRUD, update, import, dry-run, apply action and teardown on an isolated bridge. Fixes: SDN subnets are created by CIDR but addressed as `<zone>-<ip>-<prefix>` — new `EchoName` attribute rule (response field differing from request field), `NoPathParam`, computed path identifiers (`subnet_id`) carried from state on update, filtered-list read on `cidr`; import IDs now split with `SplitN` so components may contain the separator (`vnet/10.0.0.0/24`); constant `type` attributes on vnet/subnet are no longer user-facing; `digest` is no longer a resource attribute anywhere. Phase 8 (cluster create is root@pam-only) and Phase 12 (Ceph packages not installed on the node) suites are written and skip with instructions when their prerequisites are absent.
- Live acceptance (Phases 1, 2, 3, 4, 5, 6): container lifecycle/actions/snapshots and the scoped node-system suite included. Additional fixes: empty-string echoes no longer skew imports, container snapshot reads use the filtered-list shape (mirroring QEMU), container `digest` is excluded from state, and `rootfs` normalization is documented (unset in config; PVE materializes the volume path).
- Live acceptance (Phases 1, 2, 3, 5): VM lifecycle/ISO-boot/snapshot-rollback/clone scenarios included. Live testing surfaced and fixed: apidoc defaults PVE rejects (vcpus=0, vmgenid=1), Optional+Computed merges that never converge on PVE's echo-only-set-keys reads (plain Optional now), unknown Optional+Computed resolution from read-backs, indexed slot params (ide[n]/net[n]) exposed as explicit slot attributes, filtered-list reads for snapshots, clone parameter forwarding (name/full; source-id UPID no longer overwrites the new id), and import detection for identity-only state.
- Live acceptance (Phases 1, 2, 5): pool/storage/file-download scenarios included. Live testing surfaced and fixed further engine defects: path-bound attributes duplicated as request parameters (PVE 400), read-backs adopting server defaults into null optional attributes (perpetual drift), import reads now reconstruct state (required-attr-null detection), PVE append-set list params (storage content) modeled as string sets, and per-write conflict tokens (`digest`) excluded from state.
- Live acceptance (Phase 1 + Phase 2): token auth round-trip, invalid-credentials diagnostic, 11 inventory data sources, node-agreement and `nextid()` scenarios against a real node. Live testing surfaced and fixed generator bugs: typeless response properties, apidoc array-quirk responses (raw-JSON result attributes), list elements without schemas, and optional API parameters becoming required provider-function arguments (`nextid()` is zero-arg).
- Verification: `go build`, `go vet`, `golangci-lint`, unit tests throughout — parser invariants (449 families), generator audit, registry schema smoke test over all 222 types, and httptest-backed engine tests for CRUD/task/staged-apply/action/function flows. Live-cluster `TF_ACC` acceptance suites remain to be run against a lab.

## 0.1.0 (unreleased)

Phase 1 — foundation ([ROADMAP.md](ROADMAP.md)):

- Provider `pve` replaces the HashiCorp scaffold: module `github.com/dwhoban/terraform-provider-pve`, address `registry.terraform.io/dwhoban/pve`.
- Provider configuration with credential resolution: static config > environment variables; API token (`PVE_API_TOKEN`) or username/password + optional TOTP (`PVE_USER`/`PVE_PASSWORD`/`PVE_TOTP`), `api_url`, `insecure`, `ca_cert`, `request_timeout`, and plan-time credential validation (skippable).
- PVE REST client: `/api2/json` envelope handling, typed API errors, TLS options, retry with backoff on idempotent GETs, session-ticket auth with automatic re-authentication.
- Task engine: UPID parsing and polling with timeout, exit-status errors carrying the task log tail.
- New data source: `pve_version`.
